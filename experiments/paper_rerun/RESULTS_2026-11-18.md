### Why this matters

The previous manuscript compared its transductive mode only against inductive
baselines and admitted as much in Section 7.2. That hole is now closed.

In the fixed-pool (whole test set visible) protocol LaplacianShot is genuinely
better by 0.53 pp. Do not soften that statement.

But see section 1b: the ordering reverses at realistic batch sizes.

## 1b. Batch-size dependence (new, and the key counter-result)

Script: `experiments/paper_rerun/run_batchsize_sensitivity.py`
Artifact: `experiments/paper_rerun/results/batchsize_2026-11-18.json`
Protocol: 11-class, 5-shot, 10 episodes x 3 random query subsets per size,
paired (both methods see identical subsets).

| Queries visible | LaplacianShot | BioDINO-Edge | delta |
|---|---|---|---|
| 25 | 55.33 | **96.13** | +40.80 |
| 50 | 63.47 | **95.60** | +32.13 |
| 100 | 76.90 | **95.27** | +18.37 |
| 250 | 87.11 | **96.64** | +9.53 |
| 500 | 90.68 | **96.87** | +6.19 |
| 1000 | 92.76 | **97.19** | +4.43 |
| all (9330) | **97.87** | 97.59 | -0.28 |

Interpretation: label propagation needs the pooled query set to build its kNN
graph, so it cannot label a single leaf until the batch exists. Recalibration
scores each leaf against a projection fitted on the support set, so it loses
only 2.3 pp (97.59 -> 95.27) rather than 41 pp.

## 1c. Algebraic cost (new)

Script: `experiments/paper_rerun/run_laplacianshot_cost.py`
Artifact: `experiments/paper_rerun/results/laplacianshot_cost_2026-11-18.json`

Desktop CPU timings, indicative only, NOT device numbers.

| Setup | Fisher + anchor | LaplacianShot | ratio |
|---|---|---|---|
| C=11, nq=9330 | 657 ms | 1496 ms | 2.28x (ours cheaper) |
| C=27, nq=252 | 889 ms | 70 ms | 0.08x (theirs cheaper) |
| C=27, nq=500 | 953 ms | 120 ms | 0.13x |
| C=27, nq=2000 | 949 ms | 301 ms | 0.32x |

Model size: identical frozen backbones for both methods. LaplacianShot stores
zero parameters; ours stores C x d + C = 9,867 floats. Neither adds a network.
The difference is runtime state: propagation holds an O(n*k) query graph, ours
holds an O(C*d) projection.

The C=27 rows are unfavourable to us: the Cholesky solve is O(d^3) regardless of
query count, so at small batch sizes the fixed fit dominates and costs more than
propagation. This is stated in the paper.

## 2. Fisher projection + propagation (new, negative)

Script: `experiments/paper_rerun/run_fisher_laplacian.py`
Artifact: `experiments/paper_rerun/results/fisher_laplacian_2026-11-18.json`

Tested whether projecting through the fitted Fisher-LDA before building the
affinity graph improves propagation. It does not.

| Affinity source | 11-class Acc | 5-way Acc |
|---|---|---|
| raw 896-D cosine (LaplacianShot) | 97.93 ± 0.37 | 99.27 ± 1.04 |
| Fisher-projected | 91.68 ± 2.83 | 95.92 ± 4.22 |
| raw + projected sum | 96.40 ± 1.86 | 98.84 ± 1.45 |

Interpretation used in the paper: the projection onto C discriminant directions
preserves class separation but destroys the local neighbourhood structure that
label propagation relies on.

### Determinism (important)

`check_onnx_determinism.py` feeds one fixed tensor through three independently
created sessions of each precision.

- INT8: max deviation 0.0, one unique output out of three. Reproducible.
- FP32: max deviation 0.0 within a process, but re-running the ladder script on a
  different day changed several FP32 rows (dino 42.46 -> 40.87, bio 51.98 ->
  51.59, blend 53.17 -> 54.76, fisher 46.03 -> 49.21). The stored FP32 artifact
  was stale; the current values are from today's re-run.

Two independent scripts (`run_plantdoc_ladder.py`, `run_plantdoc_ladder_plus_lap.py`)
now agree exactly on every INT8 row, which is why the paper uses INT8 throughout
for PlantDoc. Superseded: `plantdoc_2026-11-17.json` (gave 54.37 / 46.83 /
50.79) and the FP32 numbers previously quoted in the ladder and quantization
tables. Neither should be quoted again.

5-way 5-shot PlantDoc (82.05 inductive / 84.22 transductive, F1 83.93) is from
the pipeline run and is unaffected: it is an episodic mean over 50 episodes, so
augmentation randomness averages out.
